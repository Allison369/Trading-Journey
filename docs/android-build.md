# Android build (offline APK)

How the installable APK in `Trading Journal/` was produced, and what to change if
you regenerate `apps/mobile/android` with `expo prebuild`.

## Toolchain

| Piece    | Version / path                                                    |
| -------- | ----------------------------------------------------------------- |
| JDK      | 17 (`JAVA_HOME` = a JDK 17 install, no admin rights needed)        |
| Android  | SDK Platform 35, Build-Tools 35.0.0, NDK 26.1.10909125, CMake 3.22.1 |
| Gradle   | 8.10.2 (wrapper, checked in under `apps/mobile/android/gradle`)    |
| AGP      | 8.6.0 (from the React Native Gradle plugin)                       |

## Patches that are required

`apps/mobile/android` is generated by `npx expo prebuild --platform android`, so these
patches are lost if you regenerate it. Re-apply them before building.

### 1. Pin the Kotlin Gradle plugin to 1.9.25

`apps/mobile/android/build.gradle`:

```gradle
dependencies {
    classpath('com.android.tools.build:gradle')
    classpath('com.facebook.react:react-native-gradle-plugin')
    // Versionless resolves to 1.9.24 via React Native's dependency graph, which
    // fails expo-modules-core: "Compose Compiler 1.5.15 requires Kotlin 1.9.25".
    classpath('org.jetbrains.kotlin:kotlin-gradle-plugin:1.9.25')
}
```

### 2. Keep UTF-8 out of `_JAVA_OPTIONS`

`apps/mobile/android/gradle.properties`:

```properties
org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m -Dfile.encoding=UTF-8 -Dsun.jnu.encoding=UTF-8
```

Do **not** set `_JAVA_OPTIONS` (or `JAVA_TOOL_OPTIONS`) in the environment. Every JVM
started by Gradle then prints `Picked up _JAVA_OPTIONS: ...` to stderr, and the Android
Gradle Plugin's prefab step treats any stderr output from the prefab CLI as a failure:

```
> Task :react-native-screens:configureCMakeRelWithDebInfo[arm64-v8a] FAILED
> [CXX1210] .../react-native-screens/android/CMakeLists.txt release|arm64-v8a : No compatible library found
```

The prefab CLI itself exits 0 — the message is the AGP fallback for "unexpected stderr".

### 3. Release bundling in this npm workspace

`apps/mobile` is a member of an npm workspace, so `react-native` and `expo-router`
are hoisted to `<repo>/node_modules`. Two consequences:

- `apps/mobile/metro.config.js` (checked in) tells Metro that the workspace root
  is a watch folder, otherwise `@tradevault/core` cannot be resolved.
- Expo resolves the bundle entry relative to the **workspace root** but the React
  Native Gradle plugin passes it relative to `apps/mobile`, so a release bundle
  fails with:

  ```
  Error: Unable to resolve module ./../../node_modules/expo-router/entry.js from C:\...\tradevault/.
  ```

  Export `EXPO_NO_METRO_WORKSPACE_ROOT=1` before the build so the Metro server root
  is the app folder, matching the entry path. Stop old Gradle daemons first
  (`... GradleWrapperMain --stop`) — a reused daemon keeps its original environment.

### 4. Android 12+ splash screen

With the legacy `expo.splash` config, prebuild only writes the launch window
background. Android 12 ignores it and draws its own splash from the launcher icon,
so the artwork never appears. After prebuild, add
`apps/mobile/android/app/src/main/res/values-v31/styles.xml`:

```xml
<resources xmlns:tools="http://schemas.android.com/tools">
  <style name="Theme.App.SplashScreen" parent="AppTheme">
    <item name="android:windowSplashScreenBackground">@color/splashscreen_background</item>
    <item name="android:windowSplashScreenAnimatedIcon">@drawable/splashscreen_logo</item>
  </style>
</resources>
```

`MainActivity` already uses `@style/Theme.App.SplashScreen`, so no manifest change is
needed. The artwork in `splash-icon.png` is composed inside the 192/288 dp safe circle
(66.7% of the image, 341 px radius at 1024²), so the circular mask never crops the
wordmark. Re-check that if you redesign the splash:

```powershell
Add-Type -AssemblyName System.Drawing
$bmp = [System.Drawing.Bitmap]::FromFile("apps\mobile\assets\splash-icon.png")
# every pixel with alpha > 64 should be within 341 px of (512, 512)
```

## Build

```powershell
cd apps/mobile/android
$env:JAVA_HOME   = "C:\path\to\jdk-17"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:EXPO_NO_METRO_WORKSPACE_ROOT = "1"
java -cp gradle\wrapper\gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain `
     assembleRelease "-PreactNativeArchitectures=armeabi-v7a,arm64-v8a" --console=plain
```

The quoted flag is required in PowerShell: unquoted, the comma ends the argument.

`android/gradle.properties` lists all four ABIs by default. The shipped 1.0.1 APK is
built with the two ARM ABIs, which covers every real phone and is 46.7 MB instead of
88 MB; `x86`/`x86_64` only exist for emulators:

| Build                                  | Size    | Installs on            |
| -------------------------------------- | ------- | ---------------------- |
| `armeabi-v7a,arm64-v8a` (shipped)      | 46.7 MB | every phone since 2015 |
| all four (default)                     | 88 MB   | phones + emulators     |
| `arm64-v8a` only (1.0.0)               | 31.7 MB | 64-bit phones only     |

Output: `apps/mobile/android/app/build/outputs/apk/release/app-release.apk`.

Notes:

- **Windows + non-ASCII paths:** the *real* path of the project must be ASCII.
  `ninja` is not Unicode-aware, so any native module that lives under a Hebrew (or
  other non-ASCII) folder fails with:

  ```
  ninja: fatal: chdir to 'C:/.../??????/.../expo-sqlite/android/.cxx/...' - Invalid argument
  ```

  A directory junction (`mklink /J C:\tv "C:\...\tradevault"`) is **not enough** —
  Expo's autolinking resolves the real path with `fs.realpath`, so CMake still gets
  the non-ASCII folder. For this build the tree was copied to a real ASCII folder
  (`C:\tvbuild`), the three workspace junctions in `node_modules/@tradevault` were
  recreated to point inside that copy, and Gradle was run from there.
- `assembleRelease` produces a self-contained JS bundle (no Metro server needed).
  `assembleDebug` does **not** — it expects a running `expo start`.
- Release signing uses the checked-in **debug keystore**
  (`apps/mobile/android/app/build.gradle`, `signingConfigs.debug`), so the APK
  installs on a phone but is not Play-Store-updatable. Swap in a real keystore
  before distributing.
- The app is offline-first: no login, data lives in SQLite on the device. Supabase
  is only used when `app.json` → `expo.extra.supabaseUrl` / `supabaseAnonKey` are set.
- Minimum Android: 7.0 (API 24).
