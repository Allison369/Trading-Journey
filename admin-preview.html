What this page cannot do, and why
  • It cannot read anyone's trades, exits, journal, strategies, account names, balances or screenshots. There is no policy in 0002_rls_policies.sql or 0004_admin_role.sql that grants an admin that access, and the isolation suite asserts it.
  • It cannot see a password, a token or a broker credential. None of those exist in this database — the app has no broker integration, and passwords are hashed by Supabase Auth, not stored here.
  • It cannot delete an account. Deleting a user's data is not a support convenience; it is an irreversible action, and the person who should be able to take it is the account holder.
  • It cannot suspend anyone. There is no suspension concept in the schema. Adding one would need a decision about what happens to that user's records, and inventing that decision quietly would be wrong.

To bootstrap the first admin there has to be a first admin, so it is done once with database access — the exact SQL is at the bottom of supabase/migrations/0004_admin_role.sql.
